# MODERN PACKAGE MANAGEMENT WITH UV :

- dependencies are external packages a program needs
- a virtual environment isolates a project's installed packages
- uv manages Python versions, environments, dependencies and project commands
- a lockfile records the resolved versions used to recreate an environment

## Install and check

- `uv --version` checks whether uv is available
- macOS with Homebrew: `brew install uv`
- see the [installation guide](https://docs.astral.sh/uv/getting-started/installation/) for other platforms

## Start a simple application

In a new practice location:

```bash
uv init --no-package weather-practice
cd weather-practice
uv add requests python-dotenv
uv add --dev ruff
uv run python main.py
```

- `--no-package` selects a simple application layout suitable for script practice
- run project commands inside the directory containing its `pyproject.toml`
- `uv run` uses the project environment; manual activation isn't required

See [working on projects](https://docs.astral.sh/uv/guides/projects/) for the project workflow.

## What each file does

- `pyproject.toml` (project metadata, Python requirements, declared dependencies and tool configuration)
- `uv.lock` (resolved direct and indirect dependency versions; generated by uv)
- `.python-version` (preferred Python version for the project)
- `.venv/` (installed interpreter environment and packages; recreate instead of committing)
- `main.py` (entry script in the simple application layout)
- commit configuration, lockfile and Python preference; ignore `.venv/`

## Add and remove packages

```bash
uv add pandas
uv add --dev ruff
uv remove pandas
uv remove --dev ruff
uv tree
```

- direct dependencies are explicitly requested; transitive dependencies are needed by those packages
- normal dependencies support the application; development dependencies support development
- `uv add` and `uv remove` update project metadata, resolution and the environment
- `uv tree` displays the dependency tree

The [dependency guide](https://docs.astral.sh/uv/concepts/projects/dependencies/) explains dependency groups and version constraints.

## Lock, sync and run

```bash
uv lock
uv sync
uv run python main.py
```

- `lock` resolves dependencies and writes the lockfile; it doesn't install the resolved packages
- `sync` installs the selected locked dependencies into the environment
- `sync` is exact by default and can remove packages not selected by the project configuration
- `run` normally checks the lockfile and synchronizes before executing
- `uv sync --locked` fails if the lockfile needs updating
- `uv run --locked python main.py` runs without permitting lockfile changes
- `--frozen` skips the freshness check; it isn't equivalent to `--locked`
- `uv lock --upgrade-package requests` updates that package's resolution within declared constraints; sync afterwards
- new package releases alone don't automatically upgrade the locked versions

See [locking and syncing](https://docs.astral.sh/uv/concepts/projects/sync/) for these distinctions.

## Python selection

- `uv python list` lists available and installed Python versions
- `uv python install 3.14` installs a supported Python interpreter for that version
- `uv python pin 3.14` writes the preference to `.python-version`
- the preference must be compatible with `requires-python` and package requirements
- `uv run python --version` confirms the interpreter actually used

## Existing requirements.txt projects

- in a separate practice copy, initialize a project, then use `uv add -r requirements.txt` to import requirements
- `uv pip install -r requirements.txt` installs into a chosen environment but doesn't declare a uv project's dependencies
- `uv export --format requirements.txt --output-file requirements.txt` exports locked requirements for other tools; it overwrites that output file
- keep the uv project metadata as the authority after migrating, rather than independently editing two dependency lists

See the [pip migration guide](https://docs.astral.sh/uv/guides/migration/pip-to-project/) and [CLI reference](https://docs.astral.sh/uv/reference/cli/).
